# Brand-book intake questionnaire

Ask these **before generating anything**. Ask conversationally — skip or collapse questions when
earlier answers make them moot. Record answers to `intake/<project>.md`, then generate what's
missing. The two **branching** questions (logo / colors / fonts "do you have…") decide how much
the agent generates vs. ingests.

## Brand basics
1. What's the brand/company name, and in one line — what is it?
2. What industry / space is it in? What's the organizing idea that makes it *this* brand and not
   a competitor?
3. Who's the audience? Give 3–5 adjectives for the tone you want (e.g. clinical, playful,
   premium, warm, technical, bold).
4. Is there a tagline or key message?

## Existing assets — the branching questions
5. **Do you have a logo?**
   - Yes → please share the file (SVG preferred, else PNG/PDF). Is it final, or open to refinement?
   - No → we'll generate a **wordmark direction + a few candidates** for you to choose from
     (a styled text logo). It's a starting point to iterate, not a final trademark-ready mark.
6. **Do you have brand colors?**
   - Yes → exact values please (HEX at minimum; RGB; Pantone + CMYK if you print).
   - No → we'll propose a palette.
7. **Do you have brand fonts?**
   - Yes → names + where they're licensed/hosted.
   - No → we'll propose a pairing (a primary + optional secondary).
8. Do you have an **existing brand book** or any brand assets we should build on?
9. Any **reference brands/sites** you love — and any you dislike? (Both are useful.)

## Scope
10. Where will the brand live? (web / print / app / packaging / social) — this decides which
    brand-book pages matter (e.g. print → include Pantone/CMYK + minimum print size).
11. Primary language? Any secondary languages?
12. Do you need co-branding / partner lockups?

## Sign-off
13. Who approves the brand book, and what's the timeline?

---

**After intake:** summarize back what exists vs. what you'll generate, confirm, then proceed to
generate the missing pieces (per `../SKILL.md` step 3) and build the PDF. Remember the hard gate —
present and iterate until the approver signs off before any design-system/page work begins.
