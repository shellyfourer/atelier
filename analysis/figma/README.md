# Analysis — method notes from Figma sources

> Abstracted construction method learned from each source. **Teacher, not template** — method
> only, no copied values/fonts/layouts. Diversity across sources is the goal: each new source
> should teach a *different* way to build, so atelier learns method pluralism instead of
> overfitting to one "correct" system.

## By source

- **Source 01** (a large, formal, exhaustive token library): analyzed by layer below
  (color / type / space / components / composition).
- **Source 02** — [method notes](./source-02-method.md) (a lean, pragmatic agency project):
  category-color method, role-assigned multi-typeface, one-accent composition, section padding
  system. Deliberately contrasts Source 01.
- **Source 03** — [method notes](./source-03-method.md) (a data-dense dashboard on shadcn/Tailwind):
  thin-semantic token method (theme-by-mode), data-density UI, app-shell/state/role method. A
  third distinct construction method; bridges toward shadcn/React output.
- **Source 04** — [method notes](./source-04-method.md) (a Shopify storefront, warm retail):
  second independent confirmation of the ramp + type architecture, plus responsive-component
  discipline, storefront anatomy, and the page-skeleton library seed.
- **Source 05** — [method notes](./source-05-method.md) (an app-leaning store, shadcn admin register):
  reframed the color methods as composable TIERS (not either/or); added alpha-ramp tokens,
  translucent-border convention, sub-namespaced roles, and the greybox/wireframe method.
